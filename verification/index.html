    Signal fidelity¶

    A simulator is only as useful as your trust in what it emits. This page covers how the output is checked, what an independent instrument found, and what changed because of it.

    How the output is checked¶

    Layer What it checks
    Unit tests (tier1) Code generators, navigation encoders, geometry, the trajectory and Hermite maths, filters
    Integration tests (tier2) Each constellation's full signal path, multi-band coherence, array phase across 6-DoF sweeps, antenna polarisation and group delay, atmosphere
    System tests (tier3) Whole-generator runs, including the client–server path
    Code timing at every rate For every band, the code phase recovered from the output is compared with an independent reference, at integer and fractional sample rates
    End-to-end truth The generated signal is compared with the ground-truth sidecar, across a frame boundary
    Navigation encoding Message structure, parity, CRC and FEC for GPS LNAV (against an open-source decoder), Galileo I/NAV, BeiDou B-CNAV1 and D1/D2, and GLONASS strings
    Golden regression Recorded reference outputs for GPS L1, L2 and Galileo E1. Any change to the signal fails until the bank is deliberately regenerated, and each regeneration is explained.
    A real receiver PocketSDR acquires and tracks the output. Its Doppler is scored against ground truth (results).

    The test suite has about 70 modules. Run pytest -m tier1 for a fast pass, or pytest for everything.

    An independent instrument¶

    gnss-vsa is a separate GNSS vector signal analyser that treats this simulator as a device under test, never as a reference. It acquires with PocketSDR, then measures with its own open-loop correlator, so that no tracking loop can smooth away the structure it is looking for.

    Working with it changed how we read results:

    • Reproducing a number isn't confirming it. Two runs of the same code agreeing tells you nothing new. Three of the first four anomalies it reported turned out to be in the instrument, not the simulator. They were fixed upstream in gnss-vsa v0.2.0, and results from before and after that version aren't comparable.
    • A control has to differ from what it controls. Code timing is now checked against a reference that shares no code with the generator or with the instrument.

    What changed¶

    The defects below were in the simulator. Each one was measured, traced to its cause, fixed, and re-measured after the fix.

    Fixed Defect Effect After
    2026-10-08 Chips were sampled at the delayed instant instead of band-limited first Small code-timing errors that depended on the rate, and a ±0.5-sample sawtooth on BPSK jammers, identical on every element Every signal is shaped before it is delayed. Code timing within 8 × 10⁻⁵ samples at every rate; gnss-vsa's bench reads −0.0008 to +0.0004 samples.
    2026-10-08 Every code was half a sample early whenever the rate was a whole multiple of the chip rate 12.2 m of code-phase bias at 12.276 MHz, on every satellite −0.5000 → +0.0000 samples
    2026-10-08 Jammer carrier phase was interpolated in single precision and with zero rate between snapshots Phase noise that grew with range, and a carrier wobble for any moving geometry Both computed in double precision, from each snapshot's delay and rate
    2026-10-08 The BPSK jammer restarted its chip sequence every frame A code discontinuity every 100 ms Continuous chips, timed from the scenario start
    2026-10-08 A scenario naming a missing emitter file ran without jammers A clean-looking recording with no interference INIT fails and names the file
    2026-10-08 GLONASS positions came out as NaN from a freshly parsed RINEX file No GLONASS signal from new navigation files Correct positions
    2026-09-16 The Galileo E1-C pilot carried a 25-symbol secondary code that wasn't the ICD's A receiver wiping the standard CS25 couldn't integrate the pilot 380AD90, per ICD tables 22 and 24
    2026-09-15 A chip index came from floor() of a rounded value at an exact tie Bursts of code-only jumps of up to 0.2 samples (5 m), on every satellite at once 7 events → 0

    Known limits¶

    • C/N0 read off this output is not a carrier-to-noise density. The server emits no noise, and the client adds an ideal white floor with none of a real front end's noise figure or filtering. Compare C/N0 between runs, not against hardware.
    • Receivers that assume GPS-broadcast ionosphere (PocketSDR among them) leave a residual on other constellations, because the simulator applies one ionosphere to everything. That residual is correct physics and an expected result, not a simulator error.
    • BDGIM ionosphere is provisional and unvalidated. NeQuick-G isn't implemented.
    • Absolute pseudorange isn't claimed. See Ground truth.
    • Unrendered emitter types (noise and chirp) load silently. See Signals & interference.
