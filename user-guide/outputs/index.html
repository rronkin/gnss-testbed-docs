    Output files¶

    What a recording contains, how to read it, and the frame stream underneath it, for anyone writing their own client.

    A recording¶

    deploy_client.py writes one sample file per (RF band, antenna element) pair, plus metadata:

    recording_<band>_ant<m>.bin    # e.g. recording_L1_ant0.bin, recording_L5_ant3.bin
recording.json
radial_truth_<SV>.csv          # with --truth

    The bands are the RF bands that were generated (L1, L2, L5, B1, G1, G2), not the scenario keys. GPS L1, Galileo E1 and BeiDou B1C all end up in recording_L1_*.

    recording.json¶

    Field
    fs Complex sample rate, Hz
    bands RF bands, in file order
    n_ant Number of antenna elements
    start_time_gps_sec GPS time of the scenario start (seconds since 1980-01-06). See the timing note below.
    duration_s Scenario duration
    format complex64, sc16 or sc8
    active_sats Satellites actually generated, for example ["G05", "E11", "R03", "C21"]
    scenario, server_host, recorded_at Where it came from
    radial_truth Name of the truth CSV, or null

    The first sample is 0.1 s after the scenario start

    The server spends frame 0 warming up its kernels, so the stream starts at frame 1. Sample n of a recording is at

    \[t_\text{GPS} = \texttt{start\_time\_gps\_sec} + T_\text{frame} + n / f_s\]

    which is 0.1 s later than you might assume with the default 100 ms frames. A receiver's timeline therefore runs 0.1 s behind scenario time. Allow for it before you compare against ground truth.

    Sample formats¶

    --format Each sample Bytes per sample Use it for
    complex64 float32 I, float32 Q 8 Full dynamic range. Required by run_pocketsdr.py.
    sc16 int16 I, int16 Q 4 Most SDR receivers; scaled so that σ = 8192 per component
    sc8 int8 I, int8 Q, values ±1 / ±3 2 2-bit receivers such as PocketSDR; threshold at 1σ

    Samples are interleaved I₀ Q₀ I₁ Q₁ … with no header. The sc16 and sc8 scale is set from the first frame of element 0 of each band and then held fixed, so the AGC is frozen for the run.

    sc16 and sc8 invert Q

    The integer formats are written with Q negated, matching the spectral convention of MAX2771-based front ends, which PocketSDR expects. complex64 is written as is. If your receiver expects the usual convention, conjugate integer samples when you read them.

    Reading a recording¶

    import json, numpy as np

rec = "recordings/run1"
meta = json.load(open(f"{rec}/recording.json"))
fs, fmt = meta["fs"], meta["format"]

def load(band, ant, seconds=None):
    path = f"{rec}/recording_{band}_ant{ant}.bin"
    n = -1 if seconds is None else int(seconds * fs)
    if fmt == "complex64":
        return np.fromfile(path, dtype=np.complex64, count=n)
    raw = np.fromfile(path, dtype=np.int16 if fmt == "sc16" else np.int8,
                      count=-1 if n < 0 else 2 * n).astype(np.float32)
    return raw[0::2] - 1j * raw[1::2]          # undo the Q inversion

x = load("L1", 0, seconds=1.0)
X = np.stack([load("L1", m, 1.0) for m in range(meta["n_ant"])])   # elements × samples

    Signal levels¶

    In complex64 files, samples are in units of √W: mean(|x|²) is power in watts at the antenna. The client adds white noise at --noise-dbm (−174 dBm/Hz by default) across the full sample rate. At 12.276 MHz the floor is −103.1 dBm, and a −130 dBm satellite sits about 27 dB below it, as at a real antenna.

    The frame stream¶

    The server answers each GENERATE request with a JSON header, then the samples:

    {
  "status": "OK",
  "n_frames": 10,
  "shape": [4, 10, 1227600],
  "bands": ["L1", "L2"],
  "first_frame_idx": 1,
  "t_start_scenario_s": 0.1,
  "scenario_start_gps_s": 1452546018.0,
  "total_gen_time_s": 0.84,
  "total_gpu_time_s": 0.41,
  "total_gather_time_s": 0.12
}

    shape is (elements, frames, samples per frame). Then, with the zmq transport, one binary message part per band and frame, in the order L1/frame0, L1/frame1, …, L2/frame0, …. Each part is a C-ordered complex64 array of shape (elements, samples per frame). With the shm transport the header also carries shm_names, one shared-memory block per band holding the frames back to back, and no binary parts follow.

    The output is full precision with no noise and no quantisation. Noise, AGC and quantisation are the client's job, so you can model your own front end. To write your own client, start from deploy/client/deploy_client.py: it is one file, and its recv_frames handles both transports.

    The developer client¶

    experiments/rcv_pocketsdr_phase5.py is an all-in-one client for development on the GPU host. It records, quantises to PocketSDR's format (INT8X2 for one band, RAW8 for two, with a .tag file), runs PocketSDR on each element and prints a consistency table across the array:

    --- Multi-Antenna Consistency Check ---
PRN 01: CN0 spread = 0.2 dB-Hz, Doppler spread = 0.1 Hz
PRN 03: CN0 spread = 0.1 dB-Hz, Doppler spread = 0.1 Hz

    It connects to 127.0.0.1:5555 with the shm transport, so run it on the same machine as a server started with python -m gnss_sim.framework.server. --noise-seed makes a run bit-for-bit reproducible.
