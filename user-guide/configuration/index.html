    Configuration¶

    Two YAML files drive every run. They are kept apart because different people own them and they change at different rates.

    File Says Owned by Lives on Changes
    Scenario (for example config/scenario_config.yaml) What to simulate: when, where, which signals, which array, which jammers Test engineer Client; sent with each run Every run
    config/simulator_params.yaml How to simulate: sample rates, carriers, frame timing, filters, atmosphere Whoever runs the server Server; read at start-up Rarely

    Any field you leave out takes its default. A scenario of ten lines, like the quickstart's, is complete.

    Scenario¶

    Annotated example¶

    scenario.yaml
    scenario:
  # ── When ──
  start_epoch_utc: "2026-01-15T08:00:00Z"   # ISO 8601, UTC
  duration_s: 60.0

  # ── Where: either a static position… ──
  rx_latitude: 32.08                        # WGS-84, degrees north
  rx_longitude: 34.78                       # degrees east
  rx_altitude_m: 50.0                       # metres above the ellipsoid
  rx_orientation: [0.0, 0.0, 0.0]           # yaw, pitch, roll in degrees
  # …or a trajectory, which overrides the static position
  # receiver_trajectory: "trajectories/flight.csv"

  elevation_mask_deg: 10.0

  # ── Which signals ──
  satellites:
    rinex_nav_file: null                    # null: found in data/rinex/ by date
    constellations:
      GPS_L1:
        enabled: true
        common_power_dbm: -130.0
        sv_power_offsets_db: { G05: +3.0, G13: -2.0 }
      GPS_L2:     { enabled: true,  common_power_dbm: -130.0 }
      GPS_L5:     { enabled: false, common_power_dbm: -125.0 }
      Galileo_E1: { enabled: true,  common_power_dbm: -127.0, max_sats: 6 }
      Beidou_B1I: { enabled: false, common_power_dbm: -130.0 }
      Beidou_B1C: { enabled: false, common_power_dbm: -130.0 }
      GLONASS_L1: { enabled: false, common_power_dbm: -131.0 }
      GLONASS_L2: { enabled: false, common_power_dbm: -131.0 }

  # ── Jammers (omit the section for none) ──
  interference:
    emitter_file: "config/jammers.csv"

  # ── Antenna array: one entry per element ──
  antenna_array:
    elements:
      - id: ANT_1
        lever_arm: [0.0, -0.05, 0.0]        # forward, right, down (metres)
        orientation: [0.0, 0.0, 0.0]        # yaw, pitch, roll (degrees)
        pattern: isotropic
      - id: ANT_2
        lever_arm: [0.0, 0.05, 0.0]
        orientation: [0.0, 0.0, 0.0]

    Time and place¶

    Field Default
    start_epoch_utc 2026-01-15T12:00:00Z Scenario start. Also selects the navigation file.
    duration_s 60.0 Length of the scenario. The run is duration_s / frame_period_s frames.
    rx_latitude, rx_longitude, rx_altitude_m Paris Static receiver position (WGS-84)
    rx_orientation [0, 0, 0] Static attitude: yaw, pitch, roll, in degrees, Z-Y-X
    receiver_trajectory null Path to a trajectory CSV (on the server). Overrides the static fields.
    elevation_mask_deg 10.0 Satellites below this elevation are not generated

    Satellites¶

    Field Default
    rinex_nav_file null A path on the server, or null to search data/rinex/ and tests/data/ for the scenario date (up to five days earlier)
    constellations.<KEY>.enabled false (GPS_L1: true) Generate this signal
    …common_power_dbm -130.0 Received power for every satellite of this signal
    …sv_power_offsets_db {} Per-satellite adjustment in dB, added to the common power
    …max_sats all visible Keep at most this many satellites of this constellation, in RINEX order

    Valid keys are GPS_L1, GPS_L2, GPS_L5, Galileo_E1, Beidou_B1I, Beidou_B1C, GLONASS_L1 and GLONASS_L2. The signals table gives each one's modulation, carrier and band.

    Power is the total power of the signal at the antenna. A sample rate narrower than the signal emits proportionally less of it, as a real front end would.

    Antenna elements¶

    Field Default
    id ANT_1 Name for the element
    lever_arm [0, 0, 0] Offset from the receiver reference point in body axes, forward-right-down, in metres
    orientation [0, 0, 0] Boresight relative to the body: yaw, pitch, roll in degrees
    pattern isotropic See below

    pattern takes one of:

    • A built-in: isotropic (RHCP, unit gain), rhcp, lhcp, vpol, hpol, vdop or hdop (the last two are dipoles with sin θ gain).
    • A CST export: a path to a CST far-field .txt file on the server. Gain, polarisation and group delay are interpolated in angle.
    • Several CST exports by frequency: a map from frequency in Hz to file path. The pattern is interpolated between frequencies.
    pattern:
  1227.6e6: patterns/ant_L2.txt
  1575.42e6: patterns/ant_L1.txt

    Element m is generated for every enabled band, so the run writes bands × elements streams.

    Interference¶

    Field Default
    interference.emitter_file none Path to an emitter CSV (on the server). Leave it out for no jammers.

    Simulator parameters¶

    config/simulator_params.yaml, as shipped:

    config/simulator_params.yaml
    simulator:
  frame_period_s: 100e-3          # one frame = 100 ms of signal
  channel_period_s: 1e-3          # geometry snapshot every 1 ms
  sample_rate_hz: 12.276e6        # all bands
  carrier_freq_hz:                # centre of each RF band's stream
    L1: 1575.42e6
    L2: 1227.60e6
    L5: 1176.45e6
    B1: 1561.098e6
    G1: 1602.0e6
    G2: 1246.0e6

  polyphase_L: 256                # delay step = 1/256 sample
  polyphase_taps: 24
  polyphase_beta: 8.0
  polyphase_cutoff_frac: 0.85

  atmosphere:
    iono_model: klobuchar         # klobuchar | bdgim | none
    tropo_model: saastamoinen     # saastamoinen | none
    klobuchar_source: gps         # gps (GPSA/GPSB) | bds (BDSA/BDSB)
    bdgim_alpha: null             # 9 coefficients in TECu, required for bdgim
    rel_humidity: 0.7

pipeline:
  enable_telemetry: true
  batch_size: 10

debug:
  freeze_nav_bit: false           # force navigation data to +1
  freeze_dynamics: false          # zero delay and Doppler
    Field Default
    frame_period_s 0.1 Signal per frame, and the unit of client requests
    channel_period_s 0.001 Spacing of exact geometry evaluations. Delays between them use cubic Hermite interpolation.
    sample_rate_hz 24.552e6 (file: 12.276e6) Complex sample rate, as one number or a map per RF band
    carrier_freq_hz nominal per band Centre frequency of each RF band's output (L1, L2, L5, B1, G1, G2)
    polyphase_L 256 Fractional-delay resolution: 1/L sample. It sets only the table size, not the cost.
    polyphase_taps, _beta, _cutoff_frac 24, 8.0, 0.85 Delay filter design. Leave these alone unless you're changing the filter on purpose.
    atmosphere.iono_model klobuchar Ionosphere injected into the signal. bdgim is provisional. none gives a vacuum.
    atmosphere.tropo_model saastamoinen Troposphere. none turns it off.
    atmosphere.klobuchar_source gps Which broadcast coefficients from the RINEX header drive Klobuchar
    continuity_tolerance_m, _deg 0.001, 0.01 Largest jump allowed between trajectory segments

    Use one sample rate with deploy_client.py

    The server accepts a different rate per RF band, but the recording client records a single fs in recording.json and uses it to scale the noise. Keep sample_rate_hz a single number when you record with deploy_client.py.

    Choosing a sample rate¶

    The sample rate is the bandwidth. Every signal is band-limited to it before it is delayed: flat to 0.6 × Nyquist, −6 dB at about 0.78 × Nyquist. Code timing is exact at any rate, so choose by the bandwidth you need, not to suit the chip rate.

    sample_rate_hz Flat to Main lobes fully inside
    6.138 MHz ±1.84 MHz GPS L1 C/A, L2C, GLONASS (centre channels)
    12.276 MHz ±3.68 MHz All but L5
    24.552 MHz ±7.37 MHz All but L5, including Galileo E1's BOC(6,1) lobes
    40.92 MHz ±12.3 MHz All, including L5

    A signal wider than the flat band is still generated, band-limited, and the server logs a warning. GLONASS FDMA channels sit between −3.94 and +3.38 MHz from 1602 MHz, so at 12.276 MHz the lowest channels reach past the flat band. Use 24.552 MHz if you need every channel flat.

    Data volume and GPU time both grow linearly with the rate. See Performance.

    Timing rules¶

    \[T_s \ll T_\text{channel} \le T_\text{frame}\]
    • \(T_\text{frame} / T_\text{channel}\) must be an integer.
    • \(T_\text{channel} \times F_s\) must be an integer, so that each snapshot covers a whole number of samples. At 1 ms, any rate that is a whole number of kHz works.
