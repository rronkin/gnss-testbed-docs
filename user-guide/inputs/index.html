    Input files¶

    Besides the two YAML files, a scenario can refer to a navigation file, a receiver trajectory, an emitter list and antenna patterns. All of them are read on the server.

    Paths are resolved on the server

    Relative paths are resolved against the server's working directory, normally the project root. When recording remotely, put these files on the server first. See What lives where.

    RINEX navigation file¶

    Standard RINEX 2 or 3 broadcast navigation, mixed or single-constellation, such as the IGS daily BRDC00IGS_R_YYYYDDD0000_01D_MN.rnx. It supplies:

    • orbits and clock corrections for GPS, Galileo, BeiDou and GLONASS
    • the navigation message content each signal broadcasts
    • Klobuchar ionosphere coefficients, from the header

    Set satellites.rinex_nav_file to a path, or to null to let the server search data/rinex/, then tests/data/, for the scenario date. If the date has no file, it tries up to four days earlier. .gz files are decompressed automatically.

    The server never downloads a file. If none is found, INIT fails and names the file to fetch:

    RINEX navigation file not found for date 2026-01-15. Please download from:
https://igs.bkg.bund.de/root_ftp/IGS/BRDC/2026/015/BRDC00IGS_R_20260150000_01D_MN.rnx.gz
Then upload it using: deploy_client.py --upload-rinex <file>

    deploy/server/prepare_rinex.py --date YYYY-MM-DD does the download for you.

    Trajectory CSV¶

    Receiver motion in six degrees of freedom, as a table of polynomial segments. Each row starts a segment that lasts until the next row's t_start. Set it with scenario.receiver_trajectory.

    Columns Unit
    t_start s Segment start, from the scenario start
    x, y, z m ECEF position
    vx, vy, vz m/s ECEF velocity
    ax, ay, az m/s² ECEF acceleration
    jx, jy, jz m/s³ ECEF jerk
    yaw, pitch, roll ° Attitude (Z-Y-X)
    yaw_rate, pitch_rate, roll_rate °/s
    yaw_accel, pitch_accel, roll_accel °/s²
    yaw_jerk, pitch_jerk, roll_jerk °/s³

    Within a segment that starts at \(t_0\), each axis evolves as

    \[p(t) = p_0 + v_0\,(t - t_0) + \tfrac{1}{2}\,a_0\,(t - t_0)^2 + \tfrac{1}{6}\,j_0\,(t - t_0)^3\]
    • One row is a stationary receiver, or one moving at constant rates.
    • Past the last row, acceleration and jerk drop to zero and the receiver carries on at constant velocity.
    • Discontinuities between segments larger than continuity_tolerance_m / _deg are a fatal error at INIT. Make the trajectory continuous before you run it.

    Emitter CSV¶

    One row per jammer. Set it with scenario.interference.emitter_file. Leave columns that don't apply to a row empty.

    Defaults apply only to missing columns

    A default below is used only when the column isn't in the file at all. An empty cell in a column that the row's type reads (for example a blank freq_offset_hz on a CW row) fails at INIT. Fill in every column your emitter types use.

    Columns for every emitter¶

    Column Default
    id (required) Unique name
    type (required) CW, FM, BPSK, and also CHIRP, NARROWBAND_NOISE, BROADBAND_NOISE (which are rendered)
    geometry_mode (required) STATIONARY_LLA, the only mode implemented
    latitude_deg, longitude_deg, altitude_m (required) Location, WGS-84
    power_dbm -100 Transmit power in dBm, into the emitter's antenna
    center_freq_hz 1575.42e6 Carrier. Also chooses the RF band: the nearest of L1, L2, L5, B1, G1, G2.
    pattern isotropic Emitter antenna: a built-in name or a CST file, as for elements
    yaw_deg, pitch_deg, roll_deg 0 Emitter antenna orientation in local north-east-down axes

    Received power is computed, not given. Free-space loss at the band's carrier is applied over the true distance to the receiver:

    \[P_\text{rx} = P_\text{tx} + G_\text{tx} + G_\text{rx} + 20\log_{10}\frac{\lambda}{4\pi d}\]

    At L1 (\(\lambda\) = 0.19 m), 1 km costs 96.4 dB. A 1 W (30 dBm) jammer 1 km away arrives at about −66 dBm, which is 64 dB above a −130 dBm satellite.

    Note

    A jammer on a band with no satellites enabled adds that band to the output. For example, an L2 jammer in an L1-only scenario produces L2 files containing only the jammer. Emitters more than max(15 MHz, sample rate) from a band's centre are left out of that band. Within one band, every jammer currently uses the first jammer's antenna pattern.

    Columns by type¶

    Type Column Default
    CW freq_offset_hz 0 Tone offset from center_freq_hz
    FM freq_offset_hz 0 Centre offset
    fm_deviation_hz 1e6 Peak deviation
    fm_period_s 0.001 Triangle period
    BPSK freq_offset_hz 0 Carrier offset
    bpsk_chip_rate 1.023e6 Chips per second
    bpsk_seed 12345 32-bit seed. The same seed always gives the same code.
    CHIRP chirp_sweep_hz, chirp_period_s, chirp_direction 1e6, 0.001, UP Parsed; not rendered yet
    *_NOISE bandwidth_hz fs/2 Parsed; not rendered yet

    Antenna patterns¶

    An element's or an emitter's pattern can point to a CST far-field export (.txt). The simulator reads gain and phase for both polarisation components on a θ/φ grid, so it gets polarisation coupling and angle-dependent group delay, not just a gain. To model a pattern that changes with frequency, give one export per frequency:

    pattern:
  1176.45e6: patterns/crpa_L5.txt
  1227.6e6:  patterns/crpa_L2.txt
  1575.42e6: patterns/crpa_L1.txt

    Patterns are defined in the element's own frame: orientation turns that frame relative to the body, and the body's attitude turns it relative to the Earth.

    Conventions¶
    Positions ECEF metres (trajectories), WGS-84 degrees and metres (LLA fields)
    Body axes Forward-right-down. Lever arms are [forward, right, down].
    Euler angles Yaw → pitch → roll (Z-Y-X intrinsic), in degrees
    Time Seconds from start_epoch_utc (UTC in the YAML, GPS time inside)
    Power dBm, frequency in Hz
