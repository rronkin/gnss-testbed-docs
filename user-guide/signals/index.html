    Signals & interference¶

    What the simulator can put on the air today, and what is specified but not yet built.

    • Signals on the same RF band share one stream. GPS L1, Galileo E1 and BeiDou B1C all land in the L1 files, as they would at a real L1 front end.
    • GLONASS channels are offset from the band centre. Each satellite sits at its FDMA channel's offset from the G1/G2 carrier.
    • Navigation data is real. It is encoded from the broadcast ephemeris in the RINEX file, with the parity, CRC and FEC each ICD specifies, so a receiver can decode it.
    • Every code is band-limited to the sample rate before it is delayed (why). Code timing is exact at any sample rate.

    Interference¶

    Emitters are rows in an emitter CSV. Each has its own fixed location, transmit power, carrier and antenna pattern. Free-space path loss to the receiver is applied, and delay and Doppler are computed per antenna element, so an array sees each jammer from its true direction.

    Jammers are stationary for now

    geometry_mode: STATIONARY_LLA is the only geometry implemented. TRAJECTORY_FILE, for moving emitters, is in the interface but isn't wired up, so a row that uses it fails to load.

    Type What it emits Status
    CW A single tone, optionally offset from the band centre Rendered
    FM A carrier swept by a triangle wave: deviation and period Rendered
    BPSK A pseudo-random BPSK spreading code at any chip rate, seeded and deterministic Rendered
    CHIRP A linear sweep, up, down or triangle Loads, not rendered
    NARROWBAND_NOISE Band-limited Gaussian noise Loads, not rendered
    BROADBAND_NOISE Wide Gaussian noise Loads, not rendered
    PULSED A gated version of another type Rejected at load
    SPOOFER GNSS replicas with controlled offsets Rejected at load

    Loads, not rendered

    A CHIRP or noise row parses and loads without error, but contributes nothing to the output. Don't count on these types for jamming-to-signal ratios until they are implemented.

    BPSK emitters are shaped and delayed exactly like satellites, so each element sees its own sub-sample delay in the envelope. CW and FM have no edges, so they are computed directly at the delayed instant, which is exact for them.

    Channel effects¶

    Effect Model Status
    Geometry Light-time solution with Sagnac correction, per satellite and element On
    Satellite clock Broadcast polynomial from the navigation file On
    Troposphere Saastamoinen zenith delay with the Niell mapping function On, can be switched off
    Ionosphere Klobuchar, scaled by 1/f² per carrier On, can be switched off
    Ionosphere, BDGIM BeiDou global model, with coefficients supplied by you Provisional
    Ionosphere, NeQuick-G Not implemented
    Antenna gain and polarisation Jones-vector coupling with built-in or CST patterns On
    Antenna group delay From CST patterns, by frequency and angle On
    Thermal noise White Gaussian, added by the client (−174 dBm/Hz by default) On
    Multipath Designed to reuse the direct path's baseband Not implemented

    One ionosphere for every constellation

    The ionosphere is a property of the medium, so a single model applies to every signal in the scenario. Klobuchar coefficients come from the RINEX header, which carries them whatever constellations you enable. A receiver that corrects with a different model, such as Galileo's NeQuick, is left with a residual. That residual is real; the simulator isn't wrong.
