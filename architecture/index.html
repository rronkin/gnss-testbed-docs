    Architecture¶

    How a scenario becomes samples: the signal model, the one design decision that makes it fast, how code timing stays exact at any sample rate, and the protocol between client and server.

    The signal¶

    At antenna element m, on RF band b, the server produces

    \[r_{m,b}[n] = \sum_{k=1}^{S} x_k^b\!\left(\frac{n}{F_s} - d_{k,m}[n]\right) \cdot e^{-j\,2\pi f_c^b\, d_{k,m}[n]} \cdot g_{k,m}\]
    Term
    \(x_k^b(t)\) Baseband of source k (satellite or jammer): code, navigation data, subcarrier
    \(d_{k,m}[n]\) Total delay from source k to element m: geometry + troposphere + ionosphere − satellite clock
    \(e^{-j2\pi f_c d}\) Carrier phase. Its rate of change is the Doppler.
    \(g_{k,m}\) Complex antenna gain: both patterns and the polarisation coupling

    The delay does two things at once. It stretches and shifts the code (code Doppler), and it turns the carrier phase (carrier Doppler). The server outputs exactly this sum, with no noise. The client adds the \(w_{m,b}[n]\) term.

    Compute once, delay many¶

    The key observation: the baseband depends only on the source, while the delay depends on the source and the element.

    baseband x_k        depends on source k                 → computed once per frame
delay d_k,m         depends on (source, element)        → per pair
carrier phase       depends on (source, element, band)  → per triple
gain g_k,m          depends on (source, element)        → per pair

    So the server builds each source's baseband once, then reads it out at every element with that element's delay, phase and gain. A new antenna element adds only a delayed read of buffers that already exist, so it costs far less than a new source.

    The delay¶

    Geometry. The transmit position depends on the delay itself, so the light-time equation is solved iteratively: three fixed Newton iterations, vectorised on the GPU, to sub-picosecond precision. The Sagnac rotation is applied at every iteration. The element position is the receiver's position plus its lever arm rotated by the current attitude, \(\vec q_m = \vec q_\text{COM} + R(t)\,\vec l_m\).

    Delay budget.

    \[d = d_\text{geometric} + d_\text{tropo} + d_\text{iono}^{(b)} - d_\text{SV clock}\]
    Term Model
    Troposphere Saastamoinen zenith delay, Niell mapping function
    Ionosphere Klobuchar (IS-GPS-200), scaled by \(1/f_c^2\), so it differs per band
    Satellite clock Broadcast polynomial \(a_{f0} + a_{f1}\Delta t + a_{f2}\Delta t^2\)

    Between snapshots. Delays are evaluated exactly every channel_period_s (1 ms) and interpolated to every sample with cubic Hermite polynomials, using both the delay and its rate at each snapshot. GNSS delays are smooth, so the error is \(O(T^4)\). The interpolation adds about three multiply-adds per sample.

    Carrier phase in double precision. \(f_c \cdot d\) is about \(10^8\) cycles. Single precision would leave no usable digits in the fractional cycle that sets the phase. The phase is formed and reduced modulo one cycle in FP64, and only then cast to FP32 for the sine and cosine.

    Shaping, then delay¶

    Every signal here is piecewise constant over segments: one chip, or 1/12 of a chip for the BOC(6,1) components of Galileo E1 and BeiDou B1C. Two steps turn segments into samples:

    1. Shape (once per source). The segment waveform is convolved with a fixed zero-phase low-pass filter \(h\) and evaluated exactly at each sample instant. A piecewise-constant waveform through \(h\) is a sum of \(h\)'s step responses, one per segment edge, so a single precomputed step-response table serves every signal and every rate. Segment indices come from exact integer arithmetic, never from floor() of a float.
    2. Delay (per source × element). A polyphase fractional-delay filter, with 256 phases of 24 taps, reads the shaped buffer at \(n - d_{k,m}[n]\,F_s\). Each output sample is an independent dot product, which is why all N samples of a frame can be computed in parallel.

    The emitted spectrum is \(h\) times the delay filter's response. Both are defined in samples, so the sample rate sets the bandwidth:

    Shaping \(h\) Delay filter Together
    Flat (≤ 0.001 dB) to 0.6 × Nyquist 0.6 × Nyquist 0.6 × Nyquist
    −6 dB at 0.8 × Nyquist 0.85 × Nyquist ≈ 0.78 × Nyquist
    Stopband ≤ −112 dB beyond Nyquist −29 dB at Nyquist
    Why shape before delaying? (changed 2026-10)

    Earlier versions sampled the chips directly at each delayed instant. That moves every chip edge onto the sample grid and folds the rectangle's spectrum, which extends past \(F_s/2\), back into the band. The visible symptoms were a code-phase error of up to half a sample whenever the rate was a whole multiple of the chip rate, a small residual at fractional rates, and a ±0.5-sample sawtooth on BPSK jammers that was identical on every element. Shaping first removes all three. Measured code timing is now within 8 × 10⁻⁵ samples at every rate tested, and an independent analyser confirmed it. Whole-frame time stayed within measurement noise. More on Signal fidelity.

    GPU execution¶

    Per band, per frame:

    • Shaping kernel. One thread per output sample, for a chunk of up to 16 sources. It evaluates the composite (code × data × secondary code × subcarrier) at segment centres and sums step responses. BPSK jammers that share a chip rate are shaped in the same launch.
    • Fleet polyphase kernel. A grid of (samples ⁄ 128) × elements. Each thread loops over every satellite and BPSK jammer, doing Hermite delay, a 24-tap FIR, the carrier and the gain, and accumulates in a register. There are no atomics, and each thread writes its sum once.
    • CW / FM jammer kernel. These have no edges, so their phase is evaluated directly at the delayed instant, which is exact. Jammers are tiled across thread blocks and reduced in shared memory.

    Overlap. Geometry for frame N+1 runs on a CPU thread while the GPU renders frame N. Three CUDA streams (compute, host-to-device, device-to-host) and ping-pong output buffers keep the GPU fed, so throughput is max(geometry, render), not their sum.

    Memory. The output buffer is bands × elements × samples × 8 bytes, allocated once. Basebands add one row per satellite per band. Even 3 bands × 16 elements × 250 sources at 50 MHz fits in about 3.2 GB. The cost that does grow is moving the output: see the transport bottleneck.

    Antenna arrays¶

    Each element is placed at the receiver position plus its lever arm, rotated by the body attitude at every 1 ms snapshot. The array's geometry therefore stays correct through manoeuvres. Gains use Jones vectors. The transmitter's field (RHCP for satellites, the emitter's pattern for jammers) is rotated into the element's frame and projected onto its pattern, giving polarisation coupling and, for CST patterns, angle-dependent group delay. All elements share one time base and one baseband, so the streams are phase-coherent by construction.

    Client–server protocol¶

    ZeroMQ request/reply on one TCP port. Every request is JSON with a cmd and a client_id.

    Command Does Replies
    INIT Claim the session and start preparing a scenario in the background. Carries the scenario text. OK, or BUSY
    STATUS Report progress. Allowed from any client. Current phase. At READY: fs, M, bands, sample_rates, carrier_freqs, active_sats, start_time_gps_sec, duration_s, frame_period_s, total_frames
    GENERATE Render the next n_frames JSON header + samples (format)
    TRUTH Ground truth for one satellite of the running session CSV text and a summary
    STOP Release the session and free the GPU OK
    SHUTDOWN Exit the server process OK
    UPLOAD_RINEX Store a navigation file in data/rinex/. Allowed from any client. OK 
    sequenceDiagram
    participant C as Client
    participant S as Server
    C->>S: INIT (scenario text)
    S-->>C: OK, initialising in the background
    loop every 2 s
        C->>S: STATUS
        S-->>C: LOADING_CONFIG → PREPARING_EPHEMERIS → CALCULATING_VISIBILITY → INITIALIZING_GENERATOR → COMPILING_KERNELS
    end
    S-->>C: READY (fs, M, bands, satellites, …)
    loop until duration
        C->>S: GENERATE n_frames=10
        S-->>C: header + complex64 buffers
    end
    C->>S: TRUTH (optional)
    S-->>C: CSV
    C->>S: STOP
    S-->>C: OK (session released)

    COMPILING_KERNELS includes a warm-up render of frame 0, which is why the stream starts at frame 1. A session left idle for 120 s is released automatically.

    What's planned¶

    Status
    Moving jammers (TRAJECTORY_FILE) Specified; the emitter geometry is not yet connected
    Noise and chirp jammers Loaded, but they need a render path: inline phase for chirp, a shaped path for noise
    Multipath Designed to reuse the direct path's baseband buffer with extra delayed reads
    Multi-GPU Split by antenna element, broadcasting the shared baseband over NVLink
    Faster transport Shared memory exists for same-host clients. GPUDirect and other zero-copy paths are next.
