    Monitoring¶

    The server publishes Prometheus metrics on port 8000 from the moment it starts. A ready-made Docker stack adds Prometheus, Grafana, and host and GPU exporters, with dashboards already provisioned. All of it is optional: the server runs the same without it.

    Start the stack¶

    On the server, from the project root (needs Docker with Compose, and the NVIDIA Container Toolkit for the GPU exporter):

    ./deploy/server/start_telemetry.sh        # = docker compose up -d
    Service Port What it is
    Grafana 3000 Dashboards. Anonymous access with the admin role, so keep it on the lab network.
    Prometheus 9090 Scrapes every second; data kept in ./prometheus_data
    node-exporter 9100 CPU, memory, disk, network
    dcgm-exporter 9400 GPU utilisation, memory, power, temperature

    Prometheus reaches the simulator at host.docker.internal:8000. The targets are in config/prometheus.yml, the dashboards in config/grafana/provisioning/.

    Dashboards¶

    Dashboard Shows
    GNSS Telemetry Frame time split into GPU, gather and transport; real-time factor; throughput per band; satellites, jammers and antennas per band
    GNSS Navigation Receiver position on a map, speed and heading, satellite sky plot (elevation and azimuth), jammer locations
    Node Exporter Host resources
    DCGM Exporter GPU resources

    Server metrics¶

    The ones you're most likely to chart:

    Metric Type Meaning
    simulation_realtime_factor gauge Simulated seconds per wall-clock second. ≥ 1 means real time.
    processing_time_seconds summary Time to generate one batch
    gpu_processing_time_seconds summary GPU kernel time
    gather_time_seconds summary Device-to-host copy and gather
    transport_time_seconds summary Sending frames to the client
    frames_generated_total counter Frames since the server started
    gnss_sim_total_throughput_bytes_per_sec gauge Output data rate, all bands
    gnss_sim_band_throughput_bytes_per_sec{band} gauge Output data rate per band
    gnss_sim_band_sample_rate_hz{band} gauge Sample rate per band
    gnss_sim_band_satellites_count{band,constellation} gauge Satellites being generated
    gnss_sim_band_jammers_count{band} gauge Jammers being generated
    gnss_sim_total_antennas gauge Array size
    gnss_sim_sat_elevation_deg{sat_id}, …_azimuth_deg gauge Look angles per satellite
    simulation_rx_latitude_deg, …_longitude_deg, …_altitude_m, …_speed_mps, …_heading_deg gauge Receiver state
    simulation_time_utc_seconds gauge Current simulated time (Unix seconds)

    To check that metrics are flowing without Grafana: curl -s http://<server>:8000/metrics | grep simulation_.

    Where the time goes

    With large arrays, transport_time_seconds often exceeds the GPU time: the output is bands × elements × samples × 8 bytes per frame, and moving it costs more than computing it. Performance has the numbers.
