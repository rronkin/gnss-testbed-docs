    GPU server¶

    Set up a GPU host that serves recording clients over the network, from bare machine to a service that restarts itself.

    Check the driver¶

    nvidia-smi        # expect Driver Version ≥ 535 and CUDA Version 12.x

    If it's missing: sudo apt install -y nvidia-driver-535 && sudo reboot.

    Install Python 3.11+¶

    Ubuntu 22.04 ships Python 3.10:

    sudo add-apt-repository ppa:deadsnakes/ppa && sudo apt update
sudo apt install -y python3.11 python3.11-venv python3.11-dev

    Put the project in place¶

    /opt/gnss-testbed-design is the path the systemd unit expects.

    sudo git clone <repo-url> /opt/gnss-testbed-design
sudo chown -R $USER /opt/gnss-testbed-design
cd /opt/gnss-testbed-design

    Create the environment¶

    python3.11 -m venv .envs/gnss-sim
source .envs/gnss-sim/bin/activate
pip install --upgrade pip
pip install -e .                     # or: pip install -r deploy/server/requirements_server.txt
python -c "import cupy as cp; print(cp.cuda.runtime.getDeviceCount(), 'GPU(s)')"

    No internet on this host? See Air-gapped networks. On a Blackwell GPU, add the CUDA 12.9 libraries.

    Provide navigation files¶

    The server needs a RINEX broadcast file for each scenario date, in data/rinex/:

    python deploy/server/prepare_rinex.py --date 2026-01-15 --out data/rinex

    Run that on any internet-connected machine and copy the file over. Clients can also upload one. If a file is missing, INIT fails with the exact filename and download URL.

    Review the engine parameters¶

    config/simulator_params.yaml applies to every client of this server: sample rate, carriers, frame timing, atmosphere. The shipped sample rate is 12.276 MHz. See Configuration.

    Open the firewall¶

    sudo ufw allow from <lab-subnet> to any port 5555 proto tcp
# monitoring, if you use it:
sudo ufw allow from <lab-subnet> to any port 3000 proto tcp

    Allow trusted machines only: the port has no authentication.

    Start it¶

    From the project root:

    ./deploy/server/start_server.sh

    Prometheus metrics exposed on port 8000
GNSS Simulator Server started on port 5555

    From a client machine, check that you can reach it: python deploy_client.py --host <server-ip> --status should report "status": "IDLE".

    Driver, Python, project¶

    1. Install the latest NVIDIA driver from nvidia.com/drivers, reboot, and check with nvidia-smi.
    2. Install Python 3.11+ from python.org and tick Add python.exe to PATH.
    3. Clone the project, for example to C:\gnss-testbed-design.

    A separate CUDA Toolkit is optional: cupy-cuda12x bundles the runtime.

    Create the environment¶

    cd C:\gnss-testbed-design
python -m venv .envs\gnss-sim
.envs\gnss-sim\Scripts\activate.bat
pip install -e .

    Navigation files and parameters¶

    Same as Linux: put RINEX files in data\rinex\ and review config\simulator_params.yaml.

    Open the firewall¶

    In an administrator prompt:

    netsh advfirewall firewall add rule name="GNSS Testbed Server" dir=in action=allow protocol=TCP localport=5555 remoteip=<lab-subnet>

    Start it¶

    deploy\server\start_server.bat

    The batch file activates .envs\gnss-sim, sets PYTHONPATH and the CuPy cache, and starts the server on port 5555 with the zmq transport.

    Start-script settings¶

    start_server.sh reads three environment variables. The Windows script uses the defaults as fixed values.

    Variable Default
    GNSS_PORT 5555 ZeroMQ port
    GNSS_BIND 0.0.0.0 Bind address. Use 127.0.0.1 to accept local clients or SSH tunnels only.
    GNSS_TRANSPORT zmq zmq for remote clients, shm for same-machine only (details)

    Both scripts also set PYTHONPATH=src, CUPY_CACHE_DIR=experiments/simulation_results/.cupy_cache (compiled kernels persist across restarts) and CUPY_TF32=1. They always load config/simulator_params.yaml. To use another file, run the server directly:

    python src/gnss_sim/framework/server.py --port 5555 --bind 0.0.0.0 \
    --transport zmq --params config/my_params.yaml

    Run as a service (systemd)¶

    sudo useradd --system --home /opt/gnss-testbed-design gnss
sudo chown -R gnss /opt/gnss-testbed-design
sudo cp deploy/server/gnss-server.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now gnss-server

systemctl status gnss-server
journalctl -u gnss-server -f        # live log

    The unit runs start_server.sh as user gnss, from /opt/gnss-testbed-design, and restarts the server 10 s after a failure. Change User= and the paths in the unit if your layout differs.

    Operate it¶

    Task How
    See what it's doing deploy_client.py --host <ip> --status, or the dashboards
    Release a stuck session Wait 120 s (it expires on its own), or restart the service
    Stop the process systemctl stop gnss-server, Ctrl+C, or a client SHUTDOWN
    Change sample rate, carriers or atmosphere Edit config/simulator_params.yaml, then restart
    Update the code git pull (or apply a delta package), then restart
    Logs stdout/stderr, journalctl -u gnss-server under systemd

    Kernel compile after updates

    After an update or a cleared cache, the first INIT spends 1–3 minutes in COMPILING_KERNELS. Clients wait for it, because their status poll has no deadline. Run one short scenario after each deployment to warm the cache.
