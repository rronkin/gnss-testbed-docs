    Recording client¶

    deploy_client.py connects to a server, sends your scenario, streams the signal to disk, and can bring back the ground truth. It needs Python and two packages: no GPU, no CUDA, no simulator install.

    Install¶

    Copy deploy/client/ to the machine. Those three files are all you need:

    pip install -r requirements_client.txt     # numpy>=2.0, pyzmq
python deploy_client.py --host <server-ip> --status

    With a mirror instead of the internet: add --index-url <your-pypi-mirror>/simple.

    Record¶

    python deploy_client.py --host 10.0.0.5 \
    --scenario scenarios/crpa_test.yaml \
    --output recordings/crpa_run1 --truth

    Connect and send the scenario¶

    The client reads your scenario file locally and sends its text. Files it refers to, such as emitters, trajectories and patterns, must already exist on the server.

    Wait for READY¶

    The server loads the configuration and ephemeris, works out which satellites are visible, builds the generator and compiles kernels. The client polls every 2 s and prints each phase. If the server is in use, you get BUSY and the client exits.

    Stream¶

    Frames arrive in batches (--batch-size, default 10 × 100 ms). The client adds thermal noise and writes one file per band and antenna element.

    Truth, metadata, release¶

    With --truth, the client fetches the ground truth while it still holds the session, writes recording.json, and sends STOP. The session is released even after Ctrl+C or an error.

    Options¶

    Option Default
    --host (required) Server hostname or IP
    --port 5555 Server port
    --scenario (required to record) Scenario YAML on this machine
    --output ./recordings Output folder. Existing .bin files with the same names are overwritten.
    --format complex64 complex64, sc16 or sc8. See sample formats.
    --noise-dbm -174.0 Thermal noise density added to every stream (dBm/Hz)
    --max-sats 12 Cap on the number of satellites the server generates
    --batch-size 10 Frames per request
    --truth [SV] off Fetch ground truth after recording. Bare --truth takes the first generated satellite; --truth G05 picks one.
    --truth-rate-hz 10 Rows per second in the truth CSV (0 = every internal step)
    --status Print the server's status and exit
    --upload-rinex FILE Upload a navigation file to the server and exit

    --max-sats caps the whole run

    The server applies this cap across the whole run, on top of any per-constellation max_sats in the scenario. Satellites are kept in RINEX order, not by elevation. If you need every visible satellite of a big multi-constellation scenario, raise it.

    What you get¶

    recordings/crpa_run1/
├── recording_L1_ant0.bin
├── recording_L1_ant1.bin       # one file per (band, element)
├── recording_L2_ant0.bin
├── recording_L2_ant1.bin
├── radial_truth_G05.csv        # only with --truth
└── recording.json

    recording.json holds everything you need to read the samples back:

    {
    "fs": 12276000.0,
    "bands": ["L1", "L2"],
    "n_ant": 2,
    "start_time_gps_sec": 1452546018.0,
    "duration_s": 60.0,
    "format": "complex64",
    "active_sats": ["G05", "G13", "G14", "G15", "G17"],
    "scenario": "scenarios/crpa_test.yaml",
    "server_host": "10.0.0.5",
    "recorded_at": "2026-10-09T08:30:00+00:00",
    "radial_truth": "radial_truth_G05.csv"
}

    The Output files page covers the formats, the timing of the first sample and how to load the files.

    Upload a navigation file¶

    If INIT fails with RINEX navigation file not found, the message names the file and its URL. Download it on any connected machine (or run prepare_rinex.py --date YYYY-MM-DD there), then:

    python deploy_client.py --host 10.0.0.5 --upload-rinex BRDC00IGS_R_20260150000_01D_MN.rnx.gz

    The server stores it in data/rinex/ and decompresses .gz files. You need to do this once per date, for all users.

    Check a recording with PocketSDR¶

    run_pocketsdr.py turns a complex64 recording into PocketSDR's 2-bit format, writes the .tag file and runs the tracker:

    python run_pocketsdr.py --input recordings/crpa_run1 --pocketsdr C:\PocketSDR
python run_pocketsdr.py --input recordings/crpa_run1 --pocketsdr C:\PocketSDR --antenna 1 --signals L1CA L2CM
python run_pocketsdr.py --input recordings/crpa_run1 --pocketsdr C:\PocketSDR --mode acq
    Option Default
    --input (required) Recording folder (reads recording.json)
    --pocketsdr (required) PocketSDR root, containing app/ or bin/
    --antenna 0 Element to process
    --signals from the bands PocketSDR signal names, for example L1CA L2CM L5I E1B E1C
    --mode trk trk (tracking) or acq (acquisition only)
    --rx-type from mode trk_py / acq_py uses PocketSDR's Python receiver if the binaries aren't built

    The output is a tracking log with C/N0, Doppler and code phase for each satellite. With enough signal for navigation data, NMEA and RTCM files are written too.

    A C/N0 read from this output is not a carrier-to-noise density

    The server emits no noise. The client adds an ideal white floor, and the recording carries nothing of a real front end's noise figure or filtering. Use the tracker's C/N0 to compare runs with each other, not as an absolute figure.
