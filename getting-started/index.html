    Quickstart¶

    Record your first simulated GNSS signal on one machine, in about fifteen minutes. At the end you will have ten seconds of GPS L1 C/A as raw IQ, plus the ground truth it carries.

    What you need

    • A Linux or Windows machine with an NVIDIA GPU: compute capability 7.0 or newer (RTX 20-series onwards), driver 535 or newer. Check with nvidia-smi.
    • Python 3.11+ and git. On Windows, Anaconda or Miniconda as well.
    • About 2 GB of free disk, and internet access once, to download a navigation file.

    No GPU here? The recording client runs anywhere. See Deploy to use someone else's server.

    Get the code and install it¶

    git clone <repo-url> gnss-testbed-design
cd gnss-testbed-design
bash scripts/setup_env.sh
source .envs/gnss-sim/bin/activate

    setup_env.sh creates a virtual environment, installs the simulator in editable mode with its dependencies (CuPy for CUDA 12 included), and builds PocketSDR into tools/ for later verification. It puts the environment in /root/.envs and links it as .envs.

    Not running as root?

    /root isn't writable for normal users. Choose another location: ENV_ROOT="$HOME/.envs" bash scripts/setup_env.sh

    git clone <repo-url> gnss-testbed-design
cd gnss-testbed-design
scripts\setup_env.bat
conda activate gnss-sim

    setup_env.bat creates the gnss-sim conda environment, installs the simulator in editable mode with its dependencies, and sets up PocketSDR in tools\.

    Installing CuPy can take several minutes. Other ways to install, including one with no internet access, are on the Installation page.

    Check that Python can use the GPU¶

    python -c "import cupy as cp; print(int((cp.arange(4) ** 2).sum()))"

    You should see 14, which means a kernel ran on the GPU. A CUDA error here means the driver and CuPy don't match. See Troubleshooting.

    Download a navigation file¶

    Satellite orbits come from a RINEX broadcast navigation file for the scenario's date. The server does not download one for you. Fetch it once into data/rinex/:

    python deploy/server/prepare_rinex.py --date 2026-01-15 --out data/rinex

    This saves BRDC00IGS_R_20260150000_01D_MN.rnx.gz. The server decompresses it on first use. When a scenario sets rinex_nav_file: null, the server looks in data/rinex/ for a file matching the scenario date (or up to five days earlier).

    Describe the scenario¶

    Save this as config/my_first_scenario.yaml. It defines a static receiver in Tel Aviv, GPS L1 C/A from every satellite above 10°, one antenna, and ten seconds of signal.

    config/my_first_scenario.yaml
    scenario:
  start_epoch_utc: "2026-01-15T12:00:00Z"
  duration_s: 10.0
  rx_latitude: 32.08
  rx_longitude: 34.78
  rx_altitude_m: 50.0
  elevation_mask_deg: 10.0

  satellites:
    rinex_nav_file: null          # found in data/rinex/ by date
    constellations:
      GPS_L1:
        enabled: true
        common_power_dbm: -130.0

  antenna_array:
    elements:
      - id: ANT_1
        lever_arm: [0.0, 0.0, 0.0]
        orientation: [0.0, 0.0, 0.0]

    The sample rate is not set here. It belongs to the server, in config/simulator_params.yaml, and ships at 12.276 MHz. Why the split →

    Start the server¶

    Open a terminal in the repository root. The server resolves data/rinex/ and its output folder relative to the directory it starts in.

    ./deploy/server/start_server.sh

    conda activate gnss-sim
set CUPY_TF32=1
python -m gnss_sim.framework.server --transport zmq --params config\simulator_params.yaml

    When it's ready, it prints:

    Prometheus metrics exposed on port 8000
GNSS Simulator Server started on port 5555

    Leave it running. It's idle until a client connects.

    Record¶

    In a second terminal, activate the environment again, then:

    python deploy/client/deploy_client.py --host 127.0.0.1 \
    --scenario config/my_first_scenario.yaml \
    --output recordings/first --truth

    The client sends your scenario to the server, waits while the server prepares, streams the frames to disk, then asks for the ground truth:

    Sending INIT request to server...
Current Status: LOADING_CONFIG
Current Status: PREPARING_EPHEMERIS
Current Status: CALCULATING_VISIBILITY
Current Status: INITIALIZING_GENERATOR
Current Status: COMPILING_KERNELS
Current Status: READY
Server ready: fs=12.28 MHz, M=1 antennas, bands=['L1'], duration=10.0s (100 frames)
Progress: 100.0%
Recording complete.

Requesting ground truth from server...
  satellite  G05 on GPS_L1
  wrote      101 rows to recordings/first/radial_truth_G05.csv
Metadata saved to: recordings/first/recording.json
Session released successfully.

    The first run is slow, and that's expected

    COMPILING_KERNELS compiles the CUDA kernels just in time. The first run after installing can take 1–3 minutes. The kernels are then cached, and later runs reach READY in seconds.

    Look at what you recorded¶

    recordings/first/
├── recording_L1_ant0.bin     # 982 MB: complex64 IQ, 12.276 MS/s, 10 s
├── recording.json            # sample rate, bands, satellites, GPS start time
└── radial_truth_G05.csv      # range, range rate, Doppler, delay per 0.1 s

    Your satellite may not be G05. Bare --truth picks the first satellite the server generated.

    A quick check in Python:

    import json, numpy as np

meta = json.load(open("recordings/first/recording.json"))
fs = int(meta["fs"])
x = np.fromfile("recordings/first/recording_L1_ant0.bin", dtype=np.complex64, count=fs)  # first second

print(meta["active_sats"])
print("total power: %.1f dBm" % (10 * np.log10(np.mean(np.abs(x) ** 2)) + 30))

    Expect about −103 dBm. That is the thermal noise the client adds (−174 dBm/Hz over 12.276 MHz). The satellites, at −130 dBm each, sit well below it, as they do at a real antenna. Samples are in units of √W, so |x|² is power in watts.

    Optional: check it with a receiver¶

    The setup script built PocketSDR, an open-source multi-band receiver. Have it acquire and track the recording:

    python deploy/client/run_pocketsdr.py --input recordings/first --pocketsdr tools/PocketSDR-master

    It quantises the recording into PocketSDR's format, runs the tracker, and writes a tracking log with C/N0 and Doppler for each satellite. Compare the Doppler with radial_truth_G05.csv. The Ground truth page explains the 0.1 s offset you'll need to allow for.

    Stop the server with Ctrl+C when you're done.
