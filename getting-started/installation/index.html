    Installation¶

    The simulator has two parts with very different needs. The server needs an NVIDIA GPU and the full Python stack. The recording client needs Python and two packages, and runs on any machine.

    Requirements¶

    Server¶

    Minimum Recommended
    GPU NVIDIA, compute capability ≥ 7.0, 8 GB VRAM (RTX 2080 / T4 class) RTX 5090, RTX PRO 4500, or a datacenter GPU
    NVIDIA driver 535 (CUDA 12.x) latest
    CPU / RAM 4 cores / 16 GB 8+ cores / 32+ GB
    Disk 10 GB fast SSD sized for your recordings (see below)
    OS Ubuntu 22.04+ or Windows 10/11 Linux for long-running servers
    Python 3.11 3.12

    VRAM is rarely the limit. Even the largest configuration we size for, with 3 bands, 16 elements, 250 sources and 50 MHz, needs about 3.2 GB. What drives the choice of GPU is speed. See Performance.

    Recordings are big

    A complex64 recording takes 8 bytes per sample, per band, per element. At 12.276 MHz that is about 98 MB per second of signal for one band and one antenna, so a 60 s, 4-element, dual-band run is about 47 GB. The client can write 16-bit or 2-bit samples instead (formats).

    Client¶

    Python 3.10+ with numpy>=2.0 and pyzmq. It needs no GPU, no CUDA and no copy of the simulator, only the deploy/client/ folder. See Recording client.

    Install the server¶

    The setup scripts create the environment, install the package in editable mode with its dev extras, and build PocketSDR into tools/ for signal verification.

    Linux

    bash scripts/setup_env.sh                 # once
source .envs/gnss-sim/bin/activate        # every new shell

    The environment goes in /root/.envs/gnss-sim, or /workspace/.envs if /root doesn't exist, and is linked into the project as .envs. For a non-root user, set the location yourself: ENV_ROOT="$HOME/.envs" bash scripts/setup_env.sh.

    Windows (needs Anaconda or Miniconda)

    scripts\setup_env.bat
conda activate gnss-sim

    python3.11 -m venv .envs/gnss-sim
source .envs/gnss-sim/bin/activate        # Windows: .envs\gnss-sim\Scripts\activate.bat
pip install --upgrade pip
pip install -e ".[dev]"

    pyproject.toml is the single source of dependencies. CuPy comes in as cupy-cuda12x, which bundles its own CUDA runtime, so a separate CUDA Toolkit install is optional.

    Keep the environment at .envs/gnss-sim. The server start scripts look for it there.

    For machines that install from a package mirror with no build step:

    python3.11 -m venv .envs/gnss-sim
source .envs/gnss-sim/bin/activate
pip install -r deploy/server/requirements_server.txt \
    --index-url <your-pypi-mirror>/simple
export PYTHONPATH="$PWD/src"              # the start scripts set this for you

    The full offline procedure is in Air-gapped networks.

    Blackwell GPUs (RTX 50-series, RTX PRO Blackwell)¶

    Compute capability 12.0 needs the CUDA 12.9 runtime libraries. Add them to the environment:

    pip install --upgrade nvidia-cuda-runtime-cu12 nvidia-cuda-nvrtc-cu12

    On Linux, deploy/server/start_server.sh puts these pip-installed libraries on LD_LIBRARY_PATH automatically. On RunPod, source scripts/runpod_init.sh at the start of each session does the upgrade, the library paths and the activation in one step.

    Check the install¶

    # The GPU runs a kernel (prints 14)
python -c "import cupy as cp; print(int((cp.arange(4) ** 2).sum()))"

# The generator builds and renders a frame (mocked ephemeris, no RINEX needed)
pytest tests/test_gen_smoke.py -q

# The fast unit tier
pytest -m tier1 -q

    The tests are grouped in three tiers: tier1 for fast unit tests, tier2 for integration tests and tier3 for full end-to-end runs. A bare pytest runs all of them, including the golden-signal regression.
