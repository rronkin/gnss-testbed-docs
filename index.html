    GNSS signals, generated on a GPU¶

    A software GNSS simulator for receiver and anti-jam development. It renders phase-coherent baseband IQ for every satellite, every band and every antenna element, with jammers in the same scene, and writes files that any software or hardware receiver can use.

    What it does¶

    • Multi-constellation, multi-band

      All visible satellites from a RINEX broadcast file, on every enabled band at once. Bands that share a carrier, such as GPS L1 and Galileo E1, are summed into one stream.

    • Antenna arrays

      M independent, phase-coherent IQ streams. Each element has a body-frame lever arm, an orientation and a radiation pattern (built-in polarisations or CST exports). Built for CRPA and null-steering work.

    • 6-DoF dynamics

      The receiver follows a piecewise-cubic trajectory: position, velocity, acceleration and jerk, plus the same for attitude, so each element's lever arm moves with it. A static receiver is a single latitude, longitude and altitude.

    • Interference in the same scene

      CW, triangle-FM and BPSK jammers, each with its own location, transmit power, carrier and antenna pattern. Path loss is applied, and each jammer is delayed per element, so the array sees where every one of them is.

    • Physics-based channel

      Light-time solution with Sagnac correction, broadcast satellite clocks, Saastamoinen troposphere with the Niell mapping function, and Klobuchar ionosphere scaled by 1/f² per band.

    • Exact code timing

      Every signal is band-limited to the sample rate before it is delayed. Code timing is exact at any rate, integer or fractional, and was confirmed by an independent signal analyser.

    • Ground truth on request

      The server can return the range, range rate, Doppler, delay and look angles that it actually generated for a satellite, so you can score a receiver against it.

    • Real navigation data

      Each signal carries its own message (LNAV, CNAV, I/NAV, B-CNAV1, D1/D2, GLONASS strings), encoded from the broadcast ephemeris with the ICD's parity, CRC and FEC, so receivers can decode it.

    • Client–server

      A GPU server generates the signal. A lightweight client (it needs only numpy and pyzmq) records it, on the same machine or across a network.

    How a run works¶

    YouScenario YAMLTime, place, signals, array, jammers
    ClientINIT, then GENERATEOver ZeroMQ, port 5555, in batches of frames
    GPU serverGeometry → shape → delay → sumEvery satellite and jammer, per band and element
    ClientNoise · quantise · writeOne .bin per band and element
    YouYour receiverSoftware, hardware, or your own algorithm

    The server does only signal generation and returns full-precision complex64 samples, with no noise and no quantisation. The client adds thermal noise, quantises if asked, and writes one file per band and element. More on the architecture →

    Why software, and why a GPU¶

    < $65K
    This approach: a GPU server and an open-source stack
    > $1M
    Commercial multi-channel, multi-band, phase-coherent RF simulators

    Most verification work doesn't need real time. Accepting a slowdown (×10 or ×20) swaps expensive RF hardware for cheap compute time: a scenario that runs overnight delivers the same signal fidelity. The cost of each frame doesn't depend on how long the scenario is, and memory doesn't grow with it, so an hour-long run costs exactly 60 times a one-minute run. Where real time matters, small arrays already get there on one GPU. See the measurements →

    Not there yet

    Jammers are stationary: moving emitters are specified but not wired up. Noise and chirp jammers are accepted in emitter files but not yet rendered. Spoofers, pulsed jammers and multipath are specified but not implemented. Multi-GPU is designed but not built. Signals & interference lists exactly what is supported.
